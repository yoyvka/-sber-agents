## Техническое видение проекта

Документ описывает минималистичное и практичное техническое решение для MVP Telegram-бота-ассистента (роль: Финансовый советник), соответствующее KISS и YAGNI. Основано на идее из `docs/idea.md`.

### 1. Технологии
- Python 3.11
- Управление зависимостями: uv
- LLM-клиент: `openai` Python client через провайдера OpenRouter
  - Модель по умолчанию: `gpt-4o-mini` (может быть заменена позже)
- Telegram интеграция: `aiogram` v3, режим polling
- Сборка/рут-задачи: `Makefile` (цели: init, run, lint — по мере необходимости)
- Логирование: стандартный модуль `logging`
- Хранение состояния: без БД на MVP; in-memory история диалога с ограничением длины
- Конфигурация: `.env` + `pydantic-settings`
- Принципы: KISS, YAGNI; никакого оверинжиниринга

### 2. Принцип разработки
- Фокус на MVP: реализуем только критичный функционал, быстрые итерации.
- Малые и частые изменения (PR/коммиты), простая структура кода.
- Без преждевременных абстракций и усложнений до подтверждения необходимости.
- Приоритет читаемости и простоты над оптимизациями.
- Ручное тестирование ключевых сценариев на старте; автотесты — по мере стабилизации.
- Минимально необходимая документация: запуск, конфигурация, эксплуатация.
- Единый стиль кода и базовые проверки: проект должен запускаться без ошибок.

### 3. Структура проекта
- `docs/` — документация (`idea.md`, `vision.md`)
- `src/` — исходный код
  - `bot/` — телеграм-бот
    - `main.py` — входная точка (polling)
    - `handlers.py` — обработчики сообщений
    - `llm.py` — обёртка для LLM (OpenRouter через `openai`)
    - `config.py` — загрузка настроек
    - `logging.py` — базовая настройка логгирования
- `pyproject.toml` — метаданные проекта
- `uv.lock` — lock-файл зависимостей
- `.env.example` — пример конфигурации
- `Makefile` — цели `init`, `run`

### 4. Архитектура проекта
- Вход: `main.py` — инициализация конфига, логгера, бота; запуск polling.
- Обработчики: `handlers.py` — принимает апдейты, извлекает `user_text`, управляет историей диалога (in-memory per user), обрезка до N последних сообщений.
- LLM-сервис: `llm.py` — функция `generate_reply(history, system_role, user_text)`, обращение к OpenRouter через `openai` client, возврат текста ответа.
- Конфигурация: `config.py` — загрузка переменных окружения (`TELEGRAM_BOT_TOKEN`, `OPENROUTER_API_KEY`, `MODEL`, лимиты истории и токенов).
- Логирование: `logging.py` — базовая настройка формата/уровня, логирование ключевых событий (запуск, запросы к LLM, ошибки).
- Хранилище: без БД в MVP; in-memory `dict[user_id] -> history` в `handlers.py`.

### 5. Модель данных
- Пользователь: `user_id: int`
- Сообщение: `{ role: 'system' | 'user' | 'assistant', content: str }`
- История диалога: `dict[user_id: list[Message]]`, хранится последние `N` сообщений
- Конфигурация (в рантайме): объект с полями `TELEGRAM_BOT_TOKEN`, `OPENROUTER_API_KEY`, `MODEL`, лимиты истории и токенов
- Ответ LLM: `{ content: str, usage?: { prompt_tokens?: int, completion_tokens?: int } }` (usage — опционально для логов)

### 6. Работа с LLM
- Клиент: `openai` через провайдера OpenRouter; модель по умолчанию: `gpt-4o-mini`.
- Роль: системный промпт фиксирует роль «Финансовый советник».
- Формирование сообщений: `[system, ...trimmed_history, user]`, история обрезается до `N` последних.
- Параметры генерации: `temperature=0.3`, `max_tokens=512`, `timeout=15s`.
- Повторы: 0 ретраев по умолчанию; 1 ретрай при `timeout`/`429` (опционально).
- Обработка ошибок: логирование и ответ пользователю «Техническая ошибка, попробуйте позже».
- Usage: при наличии метрик — логирование `prompt_tokens` и `completion_tokens`.
- Ограничение длины промпта: усечение старой части истории при превышении лимита.

### 7. Сценарии работы
- Старт: пользователь нажимает Start → бот отправляет приветствие и краткую подсказку.
- Обычное сообщение: пользователь пишет текст → ответ от LLM с учётом роли и истории.
- Команда `/reset`: очистка истории диалога пользователя.
- Сбой LLM/таймаут: бот сообщает об ошибке и предлагает повторить позже.
- Команда `/help`: краткая справка по возможностям и командам.

### 8. Подход к конфигурированию
- Источник: файл `.env` (в корне, не коммитим) + пример `.env.example`.
- Загрузка: `pydantic-settings` читает `.env` и переменные окружения.
- Ключи:
  - `TELEGRAM_BOT_TOKEN` (обязательно)
  - `OPENROUTER_API_KEY` (обязательно)
  - `MODEL` (по умолчанию `gpt-4o-mini`)
  - `HISTORY_MAX` (по умолчанию `10`)
  - `TIMEOUT_S` (по умолчанию `15`)
- Валидация: при старте проверяем обязательные ключи; падение с понятной ошибкой.
- Переопределения: только переменными окружения.
- Без динамического обновления конфигурации в MVP.

### 9. Подход к логгированию
- Библиотека: стандартный модуль `logging`.
- Базовая настройка: `basicConfig` с форматом `'%(asctime)s %(levelname)s %(name)s: %(message)s'`, уровень по умолчанию `INFO`.
- Управление уровнем: переменная окружения `LOG_LEVEL` (например, `DEBUG`/`INFO`).
- Именованные логгеры: `bot`, `llm`, `config`.
- Логируемые события:
  - запуск/останов сервиса
  - входящие сообщения (метаданные без содержимого)
  - обращения к LLM (длины сообщений, usage при наличии)
  - ошибки, таймауты, ретраи
- Вывод: только stdout на MVP, без файловых хендлеров.
