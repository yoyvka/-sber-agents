## Workflow для code-ассистента (KISS)

Опираемся на `docs/vision.md`, `docs/conventions.md` и план `docs/tasklist.md`. Действуем итерационно, без оверинжиниринга.

### Правила итераций
1) Согласование перед началом
   - Кратко предложи решение для текущей итерации из `tasklist.md`.
   - Приложи ключевые отрезки кода (фрагменты интерфейсов, сигнатуры функций, важные блоки) для ревью.
   - Дождись подтверждения.

2) Реализация
   - Реализуй согласованное минимальное решение.
   - Соблюдай `docs/conventions.md` (структура, стиль, логи, конфиг).
   - Избегай лишних абстракций, делай только необходимое для проверки.

3) Проверка
   - Запусти локально; проверь критерий из `docs/tasklist.md` для этой итерации.
   - В случае ошибок: минимальные исправления, повторная проверка.

4) Обновление прогресса
   - Обнови таблицу статусов в `docs/tasklist.md` (иконки, состояние итерации).
   - Отметь чекбоксы выполненных пунктов текущей итерации.

5) Коммит
   - Сделай коммит с понятным сообщением: `feat(iteration-X): краткое описание`.

6) Переход дальше
   - Запроси подтверждение перехода к следующей итерации.
   - После подтверждения — повторить шаги 1–5 для следующей итерации.

### Дополнительно
- Любые уточнения — задавай до реализации.
- Не логируй чувствительные данные и полный текст пользовательских сообщений.
- Если что-то не покрыто — следуй здравому смыслу и принципам KISS/YAGNI.
