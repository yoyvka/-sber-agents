# Отчёт о выполнении задания: Банковский ИИ-ассистент

## Название проекта и краткое описание

**Банковский ИИ-ассистент (AIDD Bot)** — Telegram-бот, выполняющий роль финансового советника. Бот использует LLM для генерации ответов на вопросы пользователей о финансах, инвестициях и банковских услугах. Проект реализован как MVP с минималистичной архитектурой, следуя принципам KISS и YAGNI.

## Выбранная роль ИИ-ассистента и обоснование

**Роль: Финансовый советник**

**Обоснование:**
- Финансовая тематика актуальна для широкой аудитории и имеет практическую ценность
- Роль позволяет продемонстрировать способность LLM давать структурированные, профессиональные ответы
- Финансовый советник требует баланса между доступностью объяснений и точностью информации
- Системный промпт фиксирует стиль общения: "Ты финансовый советник. Отвечай понятно и профессионально."

## Процесс разработки: основные вызовы и решения

### Вызов 1: Миграция с OpenAI API v0.x на v1.x
**Проблема:** Изначально использовался устаревший API `openai.ChatCompletion.create()`, который не поддерживается в версиях `openai>=1.0.0`.

**Решение:** Переписан код на использование нового клиента `OpenAI()` с методом `client.chat.completions.create()`. Это потребовало изменения структуры вызовов и обработки ответов.

### Вызов 2: Обработка ошибок нехватки кредитов (402)
**Проблема:** При использовании бесплатных моделей или ключей без баланса возникала ошибка 402, которая отображалась пользователю в техническом виде.

**Решение:** Реализована система обработки ошибок с вежливыми сообщениями пользователю и логированием технических деталей в консоль. Добавлен ретрай для временных ошибок (timeout, 429).

### Вызов 3: Управление конфигурацией
**Проблема:** Изначально конфигурация читалась напрямую из `os.getenv()`, что усложняло валидацию и управление настройками.

**Решение:** Внедрён `pydantic-settings` для типобезопасной загрузки конфигурации из `.env` с валидацией и значениями по умолчанию. Это упростило управление настройками и сделало код более поддерживаемым.

### Вызов 4: История диалога и память контекста
**Проблема:** Необходимо было реализовать хранение истории диалога для каждого пользователя с ограничением размера.

**Решение:** Реализовано in-memory хранилище `dict[user_id] -> list[Message]` с автоматической обрезкой истории до последних N сообщений. Это обеспечило контекстность диалога без использования внешней БД на MVP-этапе.

### Вызов 5: Тестирование различных моделей
**Проблема:** В процессе разработки требовалось тестировать разные модели и провайдеры.

**Решение:** Реализована гибкая система конфигурации с поддержкой переключения провайдера и модели через переменные окружения без изменения кода. Добавлена диагностическая информация при запуске бота.

## Что узнал нового в процессе AI-driven разработки

1. **Эффективность итеративной разработки с AI:** AI-ассистент позволяет быстро генерировать boilerplate код и структуру проекта, что значительно ускоряет начальные этапы разработки. Однако важно проверять и адаптировать сгенерированный код под конкретные требования.

2. **Важность правильной формулировки задач для AI:** Чёткое описание задачи и контекста критически важно для получения качественного результата. AI лучше работает с конкретными инструкциями и примерами.

3. **AI как инструмент для миграции и рефакторинга:** AI эффективно помогает в миграции кода между версиями API (например, OpenAI v0.x → v1.x), предлагая корректные замены устаревших методов.

4. **Баланс между автоматизацией и контролем:** Хотя AI может генерировать много кода, важно понимать каждую строку и проверять её на соответствие требованиям безопасности и производительности.

5. **Использование AI для документации:** AI отлично помогает в генерации документации, комментариев и отчётов, но требует проверки на точность и полноту информации.
